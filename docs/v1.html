SCOPE

The automated loop only.

Version 1 marks the project as it stood on September 22, 2026. This record covers proposal context, source guards, repairs, correctness replay, paired measurements, keep rules and recovery.

The evidence includes records attributed to the automated agent through experiment 45. That gives 27 entries: three baseline checks and 24 proposal attempts. Rejected proposals and interrupted attempts count as attempts, not completed GPU experiments.

Manually authored decode and prefill work is outside this story. No new GPU evaluation was run to create this documentation.

EARLY HARNESS TESTS

Why many runs have no score.

A large part of the early record came from testing the harness itself. At that point, the proposer had one chance. The two extra repair attempts had not been added yet.

If a candidate failed while applying its source, passed invalid syntax, crashed a check or stopped before benchmarking, there was no aggregate throughput to report. Those empty values describe where the run ended. They are not estimated from another experiment.

EVIDENCE

A small record with clear limits.

The checked-in evidence export retains experiment IDs, timestamps, source revisions, recorded keep flags, available throughput, workload names and the original outcome notes. It leaves out prompts, source patches and trials outside the automated loop.

RECORDED RANGE

697 to 796 tok/s.

The lower endpoint is the highest recorded challenge result, 697.2 tok/s from trial 39. The upper endpoint is the highest local geomean, 795.95 tok/s from trial 37.

Read this as a rough range

The endpoints come from different candidates and different workload sets. It is not an expected performance interval. Trial 37 was reverted, and trial 39 failed local replay.

When both measurements exist for one trial, the main article shows both as a rough observed range. When only one exists, it keeps its source label.

CURRENT LOOP

What happens to a proposal.

  1. Measure the current engine.
  2. Ask for a bounded source change.
  3. Run source checks and unit tests.
  4. Give a failed test back to the model for up to two repairs.
  5. Check public correctness before the H100 benchmark.
  6. Keep only a valid improvement with no large workload regression.
  7. Save the result and restore or merge the candidate.

The current implementation is authoritative when an older note describes an earlier stage of the harness.

Record integrity

An entry cannot record a keep that its own attached evidence contradicts. The log refuses a keep when any workload in the result reports a failed gate, or when the result is not eligible. The rule is contradiction rather than proof, so an entry that carries no measured workloads still records a decision taken elsewhere.

This followed trial 39, which was written as a keep while carrying a failed correctness gate, because an external score was allowed to outrank the local one. Every later trial then measured against a baseline the record itself marks as wrong. That row is preserved as it was written.

A run that dies before producing a result now leaves a record of the attempt, marked failed and ineligible. Without it the newest saved run was the previous one and could be read as the current one.

MEASUREMENT

Evidence you can replay.

Every run draws its sample prompts from one recorded seed, saved on the result and printed back as a flag. The candidate and the native reference are measured on the same prompts, so a paired comparison is paired in fact, and a correctness result can be replayed instead of retold.

Each replay also records the worst margin it saw, whether or not it passed. A passing run used to report no headroom at all, which made an engine sitting close to the limit indistinguishable from one with room to spare until it finally failed.

The native reference is held to its own budget of 0.75 logits, replayed against itself. That is a measurement floor rather than a verdict on any candidate, and it is calibrated: across two seeded five-sample runs of all six workloads, the reference's worst self-replay margin was 0.5, and the engine contract documents this noise as up to 0.75. When the reference exceeds it, the run has left the regime the candidate margin was calibrated in, so that workload is reported as a harness error and retried rather than charged to the candidate.
