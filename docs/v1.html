SCOPE

What these numbers mean.

The score line uses one external baseline: 670.7 tok/s from the engine before the proposal phase. Each later number is an external evaluation score or a score supplied in the project log. They are not the local six-workload geomean.

The first scored proposal came from the automated harness. Later changes involved direct assistance and engine work. They belong to the project progression, but they are not automatic harness keeps. The separate 27-entry harness archive preserves failed attempts and early checks without turning them into extra score baselines.

LATER VERIFICATION

The loop ran. It also rejected a candidate.

In a later test session, an initial L4 correctness run had two errors in ten tests because a speculative kernel rewrite did not match its callers. Restoring that API brought the rerun to 10 of 10 passed. A three-sample H100 run on the public shapes then passed its recorded gates. The reported TTFT ratios were 0.47 to 0.65, TPOT ratios 0.19 to 0.27, spread at most 0.04 and memory 13 percent of the device.

One automated proposal passed the source guard and all ten L4 unit tests without a repair. It failed the H100 benchmark and the loop restored the earlier engine. This confirms the rejection path in that session. It is not a kept performance improvement.

The same session found a shared draft table that produced different tokens across repeated calls. A per-sequence table made the repeats agree. A grouped SDPA path also showed a 7.0-logit gap at batch 32, compared with 0.25 for the Triton path, and was removed. Those were direct engine fixes made while checking the harness.

The engine on main later passed six of six local H100 workloads in a five-sample run at 731.0 local tok/s. That local result is not plotted against external scores. The reference's worst self-replay margin across twelve observations was 0.5 logits; the harness now uses a separate 0.75-logit native noise floor while leaving the candidate's 2.0-logit contract limit unchanged.

LIMITS

What remains open.

Trial 39's earlier 4.0-logit local failure did not recur in one L4 check and four H100 benches covering thirteen samples per workload. That does not explain the earlier failure. Fresh random prompts can expose a problem that later samples miss.

The later test-session figures above come from a session report. The raw GPU outputs for that session are not part of the checked-in Version 1 evidence export. Trial 39's external run ID and the last two score run IDs are also missing. The historical archive still records its original local failure.

Version 1 therefore shows real externally scored engine improvements and a working automated rejection path. It does not show an automated candidate that passed every local keep rule and independently proved a speedup.
